# 综合型科研博客网站设计说明

- 日期：2026-09-04
- 状态：已批准，可进入实施阶段
- 部署目标：GitHub Pages
- 内容后台：Pages CMS 托管版（免费）

## 1. 项目目标

建设一个兼具个人学术主页和科研博客功能的网站。网站应当：

- 清晰展示个人背景、论文、科研项目和博客文章；
- 固定结构页提供中文与英文，博客文章可选择中文或英文；
- 允许通过浏览器中的可视化后台维护内容；
- 使用公开 GitHub 仓库存储源码和内容；
- 依靠免费服务完成内容管理、构建和托管；
- 不需要维护服务器或业务数据库；
- 允许以后独立增加软件、数据集、教学等内容类型。

首期不包含评论系统、用户注册、付费功能、访问者提交表单、独立研究方向页面、可下载简历和完整页面搭建器。这些功能会增加隐私、审核或运维负担，但不影响以后按需添加。

## 2. 已选技术路线

采用以下组合：

- **Astro**：生成快速、适合搜索引擎收录的静态网站；
- **Pages CMS**：提供浏览器可视化后台，直接读写 GitHub 中的内容和媒体文件；
- **GitHub**：保存源码、Markdown、结构化数据、图片和完整修改历史；
- **GitHub Actions**：执行内容校验、BibTeX 导入、测试、构建和部署；
- **GitHub Pages**：托管构建后的静态网站。

Pages CMS 只承担编辑层，不是内容数据库。网站内容以文件为唯一事实来源，因此 Pages CMS 暂时不可用时，已发布网站不受影响，内容也可以直接在 GitHub 中编辑或迁移到其他 CMS。

## 3. 内容发布流程

日常流程为：

1. 维护者使用 GitHub 账户登录 Pages CMS；
2. 在后台编辑个人资料、论文、项目或博客并保存；
3. Pages CMS 将改动提交到公开 GitHub 仓库；
4. GitHub Actions 自动校验内容并构建 Astro 网站；
5. 仅当全部阻断性检查通过时，新的静态文件才部署到 GitHub Pages；
6. 构建失败时停止部署，线上继续保留上一成功版本。

后台保存的每次修改都形成 Git 提交，可查看历史或回退。网站不在前台暴露管理入口；维护者从 Pages CMS 托管站点进入后台。

## 4. 信息架构

顶部主导航保持精简：

1. 首页
2. 关于我
3. 论文成果
4. 科研项目
5. 科研博客
6. 中文 / English 切换

不设置独立“研究方向”“简历”“联系方式”导航项：研究兴趣放在首页和关于我；简历信息与联系方式以网页文字整合到关于我。

### 4.1 首页

首页采用已确认的“A：学术极简”方向，包括：

- 网站名称和主导航；
- 个人照片或学术头像；
- 一句主要研究陈述；
- 简短个人背景与研究兴趣；
- 三项横向数字概览：论文成果、科研项目、博客文章；
- 最近两篇已发布博客文章。

三项数字由已发布内容自动计算，不在后台手工填写，并分别链接到论文、项目和博客页面。首页不展示“精选成果”，不设置“查看论文 / 科研项目 / 关于我”重复按钮，也不提供简历下载。

### 4.2 关于我

关于我以中英文网页文字呈现：

- 个人简介与研究兴趣；
- 教育经历；
- 科研或工作经历；
- 荣誉与奖励；
- 技能；
- 学术服务；
- 邮箱、GitHub、Google Scholar、ORCID 等联系方式和学术主页链接。

页面不生成或链接可下载的简历文件。

### 4.3 论文成果

论文默认按年份倒序排列，提供年份和成果类型筛选。每条成果可展示：

- 原始标题和可选中文译名；
- 作者，突出显示站点所有者；
- 年份、期刊或会议、卷期页码；
- 成果类型和发表状态；
- DOI、论文、预印本、代码、数据、项目等可选链接；
- 可选的中英文摘要或说明。

页面标签和辅助文字中英双语；论文记录不为了语言切换而重复保存。

### 4.4 科研项目

项目列表展示标题、摘要、时间、状态和封面图。详情页可展示：

- 中英文标题与摘要；
- 项目周期、状态和个人角色；
- 背景、方法、进展和成果；
- 图片；
- 代码、演示、数据和外部主页链接；
- 关联论文。

核心项目字段要求中英文均填写，以保证两套结构页完整。

### 4.5 科研博客

每篇博客只选择一种正文语言，不要求同步翻译。博客列表支持：

- 查看全部、中文或英文文章；
- 按分类和标签筛选；
- 按发布日期倒序排列；
- 使用构建时生成的静态索引进行站内搜索，不依赖第三方搜索服务。

文章详情页包含标题、摘要、发布日期、更新时间、分类、标签、正文、目录和相关文章。提供 RSS、站点地图以及适合学术文章和代码片段的排版。

## 5. 双语与网址规则

- 中文为默认语言，中文首页位于网站根路径；
- 英文结构页统一位于 `/en/` 下；
- 中文博客使用 `/blog/<slug>/`，英文博客使用 `/en/blog/<slug>/`；
- 中英文结构页互相提供明确的语言切换链接；
- 页面输出正确的语言声明、canonical 和 hreflang 元数据；
- 项目详情页根据同一项目记录生成中英文版本；
- 单语博客只出现在对应语言列表中，不生成空白翻译页。

## 6. 后台内容模型

Pages CMS 根配置文件 `.pages.yml` 定义以下四类首期内容。

### 6.1 个人资料

个人资料是单一结构化文件，字段包括：

- 中英文姓名、头衔、简介、研究陈述和研究兴趣；
- 头像；
- 中英文教育、经历、荣誉、技能和学术服务列表；
- 联系方式和外部学术主页链接。

### 6.2 论文

论文使用一条记录一个结构化文件的集合。关键字段包括 citation key、DOI、标题、作者、年份、刊物、类型、状态、卷期页码、可选摘要和资源链接。

论文支持两种互补维护方式：

- Pages CMS 表单中新建和编辑单条记录；
- 上传 BibTeX 文件后，在 Pages CMS 中触发“导入或更新论文”GitHub Action。

BibTeX 导入规则：

1. 优先使用 DOI 匹配已有论文，没有 DOI 时使用 citation key；
2. BibTeX 是标题、作者、年份、刊物、类型和 DOI 等书目信息的权威来源；
3. CMS 是中文译名、摘要、展示状态、资源链接等站点专用字段的权威来源；
4. 重复导入必须保持幂等，不创建重复记录；
5. 所有条目先在临时结果中解析和校验；任一条目失败时不提交部分结果；
6. 成功后一次提交全部变更，并触发正常网站构建。

BibTeX 文件通过 Pages CMS 媒体区上传至固定导入目录；导入按钮使用 Pages CMS 的自定义 Actions 功能触发手动 GitHub 工作流。

### 6.3 项目

项目使用一条记录一个 Markdown 文件，正文允许富文本。标题、摘要和正文概览包含中英文字段；日期、状态、角色、链接、图片和论文关联为共享字段。

### 6.4 博客

博客使用一篇文章一个 Markdown 文件，字段包括：

- 语言：中文或英文；
- 标题、摘要和网址 slug；
- 正文；
- 发布日期与可选更新时间；
- 分类、标签和可选封面；
- 草稿状态。

草稿不会出现在生成的网站、搜索索引、RSS 或站点地图中。由于仓库是公开的，草稿源文件仍可在 GitHub 中被查看；任何保密、未发表或受限制的研究内容不得保存到该仓库。

## 7. 视觉与交互原则

- 风格：学术极简、稳重、留白充足、以排版和内容为主；
- 桌面端首页使用文字与头像并列布局，移动端自然改为单列；
- 数字概览保持克制，以细分隔线组织，不使用营销式卡片；
- 主色只用于链接、焦点和必要强调；
- 中英文使用兼容性良好的系统字体或可自托管字体，避免依赖不稳定的远程字体；
- 所有交互均可使用键盘操作，颜色对比和焦点状态满足常规无障碍要求；
- 页面在无 JavaScript 时仍可阅读；筛选和搜索可以渐进增强。

## 8. 失败处理与恢复

构建时执行以下阻断性检查：

- Astro 内容模式与必填字段校验；
- 中英文结构页和项目核心字段完整性；
- 日期、语言、slug、DOI 和内部链接格式；
- 重复 slug、重复 DOI 和重复 citation key；
- BibTeX 原子导入；
- Astro 生产构建成功；
- 核心路由冒烟测试。

内部失效链接阻止发布。外部链接由于可能暂时超时，只生成报告和警告，不阻止发布。图片缺失或路径错误属于阻断性错误。

发生失败时：

- GitHub Actions 输出具体文件和字段错误；
- 不部署失败构建；
- GitHub Pages 保留上一成功版本；
- 维护者在 Pages CMS 或 GitHub 修正内容，下一次提交自动重试；
- 必要时可通过 Git 历史回退错误提交。

## 9. 测试与验收

### 9.1 自动测试

- 内容模式与有效、无效示例测试；
- BibTeX 解析、去重、更新、字段保留和失败回滚测试；
- 语言路由、内容计数、排序、筛选和相关文章逻辑测试；
- Astro 完整构建测试；
- 首页、关于我、论文、项目、博客和 404 页面冒烟测试；
- 中文和英文导航及互链检查；
- 基本无障碍自动检查。

### 9.2 人工验收

- 桌面和手机宽度下无横向溢出、遮挡或不可读文字；
- 首页与已确认的学术极简方案一致；
- 三项数字只统计已发布内容并正确跳转；
- Pages CMS 可新增、编辑、删除和上传媒体；
- BibTeX 可批量导入，重复执行不产生重复论文；
- 中文与英文结构页内容完整，博客语言筛选正确；
- 构建失败时线上网站保持上一版本；
- 主要页面具备合理的标题、描述、分享信息和搜索引擎元数据。

## 10. 免费服务与权限边界

- 网站仓库设为公开，以使用 GitHub Pages 免费托管；
- 使用 Pages CMS 官方托管版和 GitHub 登录，不自行维护 CMS 服务；
- Pages CMS 的 GitHub App 仅授权目标网站仓库；
- GitHub Actions 使用最小所需权限：普通校验只读，部署使用 Pages 权限，BibTeX 导入工作流才具有内容写入权限；
- 仓库不保存私钥、访问令牌、未公开研究数据或个人敏感信息；
- 独立域名不是首期必要条件，未来绑定域名时不改变网站架构。

## 11. 后续扩展方式

未来可将软件、数据集、教学、荣誉或团队成员作为新的 Astro 内容集合和 Pages CMS 内容类型加入。每个新增类型拥有自己的模式、页面和测试，不修改现有论文、项目和博客文件格式。

若未来需要完整实时页面预览或更复杂的多人审批，可以在保留 Markdown 和结构化文件的前提下更换 CMS；前台 Astro 和 GitHub Pages 部署方式无需随之重建。
