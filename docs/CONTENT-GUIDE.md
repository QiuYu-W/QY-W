# 内容维护指南

本指南对应仓库的 [Pages CMS 配置](../.pages.yml)。下列步骤是待在真实后台验证的操作说明：尚未完成 GitHub 登录、授权、保存、上传及导入按钮的托管验收，也没有真实后台截图。首次使用前完成 [上线准备](OPERATIONS.md#上线准备)，截图要求见 [采集清单](images/README.md)。

## 1. 登录和选择仓库

打开 [Pages CMS](https://app.pagescms.org/)，使用 GitHub 登录。安装或配置官方 Pages CMS GitHub App 时选择 **Only select repositories**，仅勾选 `QiuYu-W/QY-W`。进入该仓库并核对当前分支。日常正式发布使用 `main`；首次试用使用维护者准备的验收分支，分支保存不会自动上线。后台读取当前分支的 `.pages.yml`，所以该分支必须已经包含这份配置。具体登录入口可参考 [官方快速开始](https://pagescms.org/docs/quick-start/)。

每次保存后检查 GitHub 中的文件差异和提交。保存成功表示内容写入仓库，是否上线还要看第 9 节的部署状态。后台不可用时，可以通过 GitHub 文件编辑器修改相同文件，再按相同校验流程处理。

## 2. 修改双语个人资料

打开“个人资料 / Profile”，它对应唯一文件 `src/data/profile/profile.yaml`，不能新建第二份资料。填写真实姓名、身份、简介和详细介绍的中文、英文两组字段。`statementZh`/`statementEn` 是首页研究陈述；`bioZh`/`bioEn` 在首页和关于我均按 Markdown 富文本显示，支持段落、强调、列表、链接和图片，因此保存后要同时检查两处排版。原始 HTML 只作为文字显示，不执行；页面的搜索与分享描述自动提取为纯文本。站内链接和图片使用 `/` 开头的站内路径，构建时会加上部署子路径。研究兴趣和技能按列表逐条填写；教育、经历、荣誉和学术服务的每条记录同时填写中英文标题及说明，可选时间留空即可。

选择头像，并填写 `portraitAltZh` 和 `portraitAltEn`，描述图片内容。填写有效邮箱以及带名称和完整 URL 的学术主页链接。`authorAliases` 是需要在论文作者列表中突出显示的本人姓名写法，应与实际论文署名一致。没有的信息保留空列表，不编造经历。保存后检查中文首页、`en/`、`about/` 和 `en/about/` 的文字、头像和联系方式。

## 3. 手动添加或更新论文

打开“论文成果 / Publications”。更新时先按标题、DOI 或 citation key 搜索已有记录，避免重复；新建时使用稳定且唯一的 citation key，建议采用字母、数字和连字符。文件按 `{citationKey}.yaml` 保存。

填写标题、逐位作者、四位整数年份、期刊或会议、类型及状态。可选中文标题、卷期页码、双语摘要和资源链接按实际材料填写。DOI 可填 `10.…/…` 或 DOI 链接，导入时会规范化匹配；资源链接必须是完整 `https://` 或 `http://` URL。

| 字段 | 可选值 |
| --- | --- |
| 类型 `type` | `journal`、`conference`、`preprint`、`book`、`chapter`、`thesis`、`other` |
| 状态 `status` | `published`、`accepted`、`in-press`、`preprint` |

论文默认 `draft: false`。还不能展示的记录应先开启草稿；不要将论文的发表状态当成网站的草稿开关。修改 citation key 前检查项目中的 `publicationKeys`，避免关联失效。保存并部署后检查两种语言的论文列表、筛选和每个资源链接。

## 4. 上传并导入 BibTeX

1. 从可信的书目工具导出已获准公开的论文，确保每条有唯一 citation key、标题、作者、年份及期刊/会议或出版者。固定文件名为 `publications.bib`。
2. 在媒体区选择“BibTeX 导入文件”，上传或替换该文件。确认 GitHub 中目标是 `imports/publications.bib`，没有变成带编号的新文件。该媒体区配置保留原文件名；图片区不是导入位置。
3. 核对当前分支。在仓库级操作中选择“导入或更新 BibTeX”，确认“开始导入”。配置的按钮启动 `Import publications` 工作流（`import-publications.yml`），使用当前分支。仅上传 `.bib` 不会执行导入。参见 [Pages CMS Actions](https://pagescms.org/docs/configuration/actions/)。
4. 到 GitHub Actions 查看导入日志中的 `created`、`updated`、`unchanged`、`failed`。全部解析和校验成功后，工作流再检查、测试、构建，一次性提交 `src/data/publications` 的变更；输入文件本身的上传提交不属于这个原子论文提交。
5. 检查生成的论文差异，再回后台补全中文标题、摘要、资源链接和展示状态。新导入论文默认不是草稿，会在成功部署后展示；导入中途不要同时手工改论文。
6. 重复导入相同文件应无重复论文、无新的论文内容提交。无变化的成功运行仍可能触发一次部署检查。`main` 成功导入后另看 `Deploy GitHub Pages`，并检查线上论文；其他分支不会自动部署。

匹配规则是：输入有 DOI 时只按规范化 DOI 匹配；输入没有 DOI 时按 citation key 匹配。因此给一条原本没有 DOI 的论文补 DOI 前，先核对已有记录并使 DOI 一致，避免被判为新记录或冲突。不要随意改 citation key，特别是项目已经引用时。

再次导入会覆盖书目字段（标题、作者、年份、刊物、类型、DOI、卷期页码；输入缺失的可选书目字段也可能被移除），保留已有中文标题、双语摘要、状态、链接和草稿标志。未在本次 BibTeX 中出现的已有论文不会被删除。重复 key/DOI、缺字段、文件名冲突或解析错误会中止整批导入；修正源文件并保存后重新启动新运行。若日志报告备份/恢复路径等文件系统异常，交给维护者处理，不手工清理恢复文件。

## 5. 添加双语项目

打开“科研项目 / Projects”。一条记录同时提供中英文标题、摘要、正文和本人角色，不要拆成两份翻译记录。`slug` 只用小写字母、数字和单个连字符，例如使用项目自己的英文短名；文件为 `{slug}.md`，发布后尽量保持不变。

填写开始日期 `YYYY-MM-DD`，结束日期可留空，状态选 `active`、`completed` 或 `paused`。正文分别填写在 `bodyZh`、`bodyEn` 富文本字段，它们保存在 Markdown 文件头中，不是博客式的单一正文。可选封面有图时填写中英文替代文字；项目链接需完整 HTTP(S) 地址。`publicationKeys` 逐项引用已有论文的 citation key。默认不是草稿，未准备好的项目先开启草稿。

部署后同一记录应产生 `projects/<slug>/` 和 `en/projects/<slug>/`。检查两套正文、语言切换、图片和论文关联。

## 6. 创建中文或英文博客

打开“博客文章 / Blog”，选择 `zh` 或 `en`，填写该语言的标题、摘要、正文、分类和标签。填写发布时间，可选更新时间留空；后台日期包含时间，保存后核对网站显示的日期。`slug` 规则与项目相同，文件按 `{slug}.md` 保存。即使两种语言，后台也应使用不同文件 slug，避免同名文件相互覆盖。

正文填写在“正文”富文本编辑器中；博客保存为字段头加 Markdown 正文。封面可选，有封面就填写 `coverAlt`。新博客默认 `draft: true`，确认可以公开展示后关闭草稿并保存。未来日期不等同于预约发布：当前展示条件是草稿标志，勿仅靠未来日期隐藏内容。

中文文章地址为 `blog/<slug>/`，英文为 `en/blog/<slug>/`；不会自动生成译文。没有对应译文时，语言切换返回目标语言博客列表。发布后检查语言/分类/标签筛选、搜索和文章正文。

## 7. 草稿与公开仓库

`draft: true` 的论文、项目和博客不进入生成页面、计数、搜索、RSS 或站点地图。草稿仍须满足字段和标识唯一性校验，错误草稿也会阻止构建。个人资料没有草稿开关。

**草稿源文件、上传的媒体、BibTeX 和提交历史仍然公开。** 把一篇已发布文章改为草稿不会撤回他人保存的副本，删除文件也不会清除 Git 历史。不要在这里存放保密论文、未公开研究数据、访问令牌或敏感个人资料。只有获准公开的素材才进入仓库。

## 8. 上传或替换图片

在“图片”媒体区或图片字段中上传。文件落在 `public/media`，内容中引用 `/media/文件名`；支持 PNG、JPG/JPEG、WebP、AVIF、SVG，后台可能将名称整理为安全文件名。上传后使用实际返回的路径，不手工加 `public/` 或仓库项目前缀。详细行为参见 [媒体配置](https://pagescms.org/docs/configuration/media/)。

头像用两种语言的头像替代文字，项目封面用两种语言的封面替代文字，博客封面用文章语言的替代文字。正文图片也应在编辑器的图片说明/alt 字段填写描述；若界面未提供该字段，检查生成 Markdown 的 `![描述](/media/文件名)`。描述图中有意义的信息，避免只写“图片”。

替换时可上传新文件并更新所有使用它的记录；确认不再被引用后再删除旧文件。若同名替换，确认它确实替换了预期文件，再检查部署后的缓存刷新效果。仓库中存在图片不代表页面已经引用它。没有权利公开的图片不要上传。

## 9. 保存后查看构建和部署

在 [仓库 Actions](https://github.com/QiuYu-W/QY-W/actions) 找到当前分支和本次保存对应的运行，打开第一条失败步骤查看原因。非 `main` 分支看 `CI`；`main` 看 `Deploy GitHub Pages` 的 `build` 和 `deploy` 两个任务；导入还要先看 `Import publications`。

排队或运行中继续等待；红色失败按 [运维指南](OPERATIONS.md#识别失败与修正内容) 修正；只有部署成功并打开其 Pages 地址检查内容后，才认定更新上线。导入工作流绿色只表示导入成功，不能替代后续部署结果。截图仍待真实运行后采集，见 [截图清单](images/README.md)。
